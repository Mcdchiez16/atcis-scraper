Tender Workflow & Documents – Summary

Zimbabwe Tender API • Generated:
Version v2.0

Overview

This summary explains how the Tender Workflow features work: assignments, document uploads, checklists, and multi-stage approvals. It also covers email notifications and key API endpoints used by clients.

Base URLs

  • HTTP: http://localhost:8096
  • HTTPS: https://localhost:8095

Auth

  • JWT required for all endpoints
  • Role-based access: Admin/Manager elevated actions

Key Components

1) Assignments

Assign tenders to users, set due dates, track status, and optionally send notification emails.

  • Create: POST /api/TenderAssignments/assign
  • My Assignments: GET /api/TenderAssignments/my-assignments
  • By Tender: GET /api/TenderAssignments/tender/{tenderId}/{tenderType}
  • Update Status: PUT /api/TenderAssignments/{id}/status

2) Documents

Upload PRAZ certificates, proposals, and supporting files. Files are stored under uploads/tenders/{tenderId}/ with GUID filenames.

  • Upload: POST /api/TenderDocuments/upload (multipart/form-data)
  • List: GET /api/TenderDocuments/tender/{tenderId}/{tenderType}
  • Download: GET /api/TenderDocuments/{id}/download
  • Update/Delete: PUT|DELETE /api/TenderDocuments/{id}

3) Checklist

Create items, use templates, and mark completion to keep tender submission on track.

  • Create: POST /api/TenderChecklist or bulk via POST /api/TenderChecklist/bulk
  • By Tender: GET /api/TenderChecklist/tender/{tenderId}/{tenderType}
  • Templates: GET /api/TenderChecklist/templates
  • Update Status: PUT /api/TenderChecklist/{id}/status

4) Approvals

Multi-stage approvals with sequential workflow (Initial Review → Technical → Final Approval). Approvers receive email notifications and respond with approve/reject/request changes.

  • Request: POST /api/TenderApprovals/request
  • Create Workflow: POST /api/TenderApprovals/workflow
  • Pending: GET /api/TenderApprovals/pending
  • Respond: PUT /api/TenderApprovals/{id}/respond

Email Notifications

Emails are sent for key workflow events. Configure SMTP in appsettings.json (Gmail requires App Password).

  • Assignment Created → Email to assignee
  • Approval Requested → Email to approver
  • Approval Response → Email to requester (approved / rejected / changes requested)

Settings: EmailSettings.SmtpHost, SmtpPort, FromEmail, Username, Password, EnableSsl

Quick Flows

Complete Submission

  1. Assign tender to user
  2. Create checklist (optionally from template)
  3. Upload required documents
  4. Update checklist as items complete
  5. Create approval workflow
  6. Approver responds to each stage

Document Management

  1. Upload document (multipart/form-data)
  2. List and download documents for the tender
  3. Update metadata or delete (Admin/Manager)
