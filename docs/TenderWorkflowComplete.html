1. System Overview

The Zimbabwe Tender API Workflow & Document Management System is a comprehensive solution for managing the complete tender lifecycle, from assignment to final approval. The system provides automated workflows, document management, task tracking, and multi-stage approval processes with integrated email notifications.

✅ Key Benefits

  • Automated Workflows: Streamline tender processing with automated task assignments and notifications
  • Complete Audit Trail: Track every action with automatic logging of who did what and when
  • Email Integration: Automatic email notifications keep team members informed
  • Document Control: Centralized document storage with version tracking
  • Task Management: Checklist system ensures nothing is missed
  • Multi-Stage Approvals: Sequential approval workflows with status tracking

2. Core Features

2.1 Tender Assignments

Purpose

Assign tenders to team members with clear instructions, due dates, and automatic email notifications. Track assignment status and workload across the team.

Key Capabilities

  • Assign tenders to specific users with detailed instructions
  • Set due dates and track completion
  • Automatic email notification to assignee
  • View all assignments (by user, by tender, or system-wide)
  • Update assignment status and add completion notes
  • Reassign tenders when needed

Assignment Statuses

Pending InProgress Completed Cancelled

API Endpoints

POST /api/TenderAssignments/assign

Assign a tender to a team member

GET /api/TenderAssignments/my-assignments

Get current user's assigned tenders

GET /api/TenderAssignments/tender/{tenderId}/{tenderType}

Get all assignments for a specific tender

PUT /api/TenderAssignments/{id}/status

Update assignment status

Example: Assign a Tender

{
  "tenderId": 123,
  "tenderType": "Live",
  "assignedToUserId": 5,
  "dueDate": "2026-02-15T00:00:00",
  "assignmentInstructions": "Please review this tender and prepare technical proposal",
  "notes": "High priority - deadline approaching"
}

2.2 Document Management

Purpose

Upload, organize, and manage all tender-related documents in a centralized location. Support for multiple document types with version control and secure storage.

Key Capabilities

  • Upload multiple document types (certificates, proposals, supporting documents)
  • Maximum file size: 50 MB per document
  • Automatic file organization by tender ID
  • Document version tracking
  • Secure download with authentication
  • Document metadata (type, description, upload date, uploader)

Supported Document Types

Document Type Description
PRAZ Certificate Procurement Regulatory Authority certificate
Tax Clearance Zimbabwe Revenue Authority tax clearance
Company Registration Certificate of incorporation and registration
Technical Proposal Technical submission addressing requirements
Financial Proposal Pricing and financial information
Tender Response Main tender submission document
Supporting Document Additional supporting documentation
Certificate of Compliance Compliance certifications
Bank Statement Financial statements and bank references
Reference Letter Client references and testimonials

API Endpoints

POST /api/TenderDocuments/upload

Upload a document (multipart/form-data)

GET /api/TenderDocuments/tender/{tenderId}/{tenderType}

Get all documents for a tender

GET /api/TenderDocuments/{id}/download

Download a specific document

GET /api/TenderDocuments/types

Get available document types

DELETE /api/TenderDocuments/{id}

Delete a document (Admin/Manager only)

📁 File Storage Location

Documents are stored in: {ContentRoot}/uploads/tenders/{tenderId}/

Files are automatically renamed with unique GUIDs to prevent naming conflicts and ensure security.

2.4 Approval Workflow

Purpose

Manage multi-stage approval processes for tenders. Create sequential approval chains where each stage must be approved before proceeding to the next. Automatic email notifications keep approvers informed.

Key Capabilities

  • Create single or multi-stage approval workflows
  • Sequential approval chains (Stage 1 → Stage 2 → Stage 3)
  • Automatic email notifications to approvers
  • Approve, reject, or request changes
  • View pending approvals requiring your action
  • Track approval history and comments
  • Required vs. optional approval stages

Approval Statuses

Pending Approved Rejected RequestChanges

Typical Approval Stages

Stage 1: Initial Review
Team Lead reviews completeness of tender documents and checklist
↓
Stage 2: Technical Review
Technical Expert evaluates technical proposal and compliance
↓
Stage 3: Financial Review
Finance Manager reviews pricing and financial documents
↓
Stage 4: Final Approval
Managing Director gives final approval for submission

API Endpoints

POST /api/TenderApprovals/request

Request approval for a specific stage

POST /api/TenderApprovals/workflow

Create complete multi-stage approval workflow

GET /api/TenderApprovals/pending

Get pending approvals for current user

GET /api/TenderApprovals/my-requests

Get approval requests made by current user

PUT /api/TenderApprovals/{id}/respond

Approve, reject, or request changes

Example: Create Multi-Stage Workflow

{
  "tenderId": 123,
  "tenderType": "Live",
  "stages": [
    {
      "stageName": "Initial Review",
      "approverUserId": 3,
      "requestDetails": "Please review tender documents for completeness",
      "isRequired": true
    },
    {
      "stageName": "Technical Review",
      "approverUserId": 5,
      "requestDetails": "Technical evaluation required",
      "isRequired": true
    },
    {
      "stageName": "Final Approval",
      "approverUserId": 2,
      "requestDetails": "Final approval before submission",
      "isRequired": true
    }
  ]
}

3. Email Notification System

Automated Email Notifications

The system automatically sends professional email notifications to keep team members informed of important events. All emails are sent via SMTP with HTML formatting for better readability.

Email Triggers

1. Tender Assignment Email

When Sent

Automatically sent when a tender is assigned to a user

Recipient

The user being assigned the tender

Email Content Includes

  • Tender title and reference number
  • Tender type (Live/Closed)
  • Due date (if specified)
  • Assignment instructions
  • Additional notes
  • Link to view tender details
  • Name of person who made the assignment

Subject Line

New Tender Assignment: [Tender Title]

2. Approval Request Email

When Sent

Automatically sent when an approval is requested from a user

Recipient

The approver user

Email Content Includes

  • Tender title and reference number
  • Approval stage name
  • Request details and requirements
  • Name of requester
  • Link to review and respond
  • Whether approval is required or optional

Subject Line

Approval Requested: [Tender Title] - [Stage Name]

3. Approval Response Email

When Sent

Automatically sent when an approver responds to an approval request

Recipient

The user who requested the approval

Email Content Includes

  • Tender title and reference number
  • Approval stage name
  • Response status (Approved/Rejected/Changes Requested)
  • Approver's comments
  • Name of approver
  • Next steps (if applicable)

Subject Lines

  • ✅ Approved: [Tender Title] - [Stage Name]
  • ❌ Rejected: [Tender Title] - [Stage Name]
  • 🔄 Changes Requested: [Tender Title] - [Stage Name]

Email Configuration

⚠️ SMTP Setup Required

Email notifications require proper SMTP configuration in appsettings.json

Configuration in appsettings.json

{
  "EmailSettings": {
    "SmtpHost": "smtp.gmail.com",
    "SmtpPort": 587,
    "FromEmail": "noreply@axissolutions.co.zw",
    "FromName": "Zimbabwe Tender API System",
    "Username": "your-email@gmail.com",
    "Password": "your-app-password",
    "EnableSsl": true
  }
}

Gmail Configuration Steps

  1. Enable 2-factor authentication on your Google account
  2. Go to Google Account Settings → Security → App Passwords
  3. Generate a new App Password for "Mail"
  4. Copy the 16-character password
  5. Use this password in the EmailSettings configuration
  6. Never use your regular Gmail password

📧 Email Delivery Tracking

The system tracks email delivery status:

  • EmailSent: Boolean flag indicating if email was sent
  • EmailSentAt: Timestamp of when email was sent
  • Failed emails are logged with error details

4. Complete Workflows

Workflow 1: Complete Tender Submission Process

Step 1: Assign Tender to Team Member
POST /api/TenderAssignments/assign
→ Email sent to assignee
↓
Step 2: Create Checklist from Template
GET /api/TenderChecklist/templates
POST /api/TenderChecklist/bulk
↓
Step 3: Upload Required Documents
POST /api/TenderDocuments/upload (multiple times)
Upload PRAZ cert, tax clearance, proposals, etc.
↓
Step 4: Complete Checklist Items
PUT /api/TenderChecklist/{id}/status
Mark items as completed as work progresses
↓
Step 5: Request Approvals
POST /api/TenderApprovals/workflow
→ Emails sent to all approvers in sequence
↓
Step 6: Approvers Review and Respond
PUT /api/TenderApprovals/{id}/respond
→ Email sent to requester with response
↓
Step 7: Final Submission
Update assignment status to Completed
PUT /api/TenderAssignments/{id}/status

Workflow 2: Document Review & Approval

Step 1: Upload Documents
Team member uploads all required documents
↓
Step 2: Document Review
Reviewer downloads and reviews all documents
GET /api/TenderDocuments/tender/{tenderId}/Live
↓
Step 3: Request Changes (if needed)
Approver requests changes via approval workflow
→ Email sent to submitter
↓
Step 4: Upload Revised Documents
Team member uploads corrected documents
System tracks version history
↓
Step 5: Final Approval
Approver confirms all documents are correct
→ Approval email sent

6. Security & Permissions

Authentication

All workflow endpoints require authentication via JWT Bearer token. Unauthenticated requests will receive a 401 Unauthorized response.

How to Authenticate

  1. Obtain JWT token via /api/Auth/login endpoint
  2. Include token in Authorization header: Bearer {token}
  3. Token expires after 24 hours (configurable)
  4. Refresh tokens available for extended sessions

Role-Based Access Control

Permission Admin Manager User
Assign tenders ✅ ✅ ✅
Upload documents ✅ ✅ ✅
Create checklist items ✅ ✅ ✅
Request approvals ✅ ✅ ✅
Respond to assigned approvals ✅ ✅ ✅
Delete documents ✅ ✅ ❌
Delete approvals ✅ ✅ ❌
View all assignments ✅ ✅ Own only

Audit Trail

Complete Activity Tracking

All workflow entities inherit from AuditableEntity, automatically tracking:

  • CreatedAt: When the record was created
  • CreatedBy: Username who created it
  • UpdatedAt: When last modified
  • UpdatedBy: Username who last modified it
  • DeletedAt: When soft deleted (if applicable)
  • DeletedBy: Username who deleted it
  • IsDeleted: Soft delete flag
  • RowVersion: Concurrency control
